  • Strongest result: a full interview-prep chain. The ChatGPT research skill was ported into Claude Code on 28 Sep and extended with an HTML report and publishing. It has produced 4 briefs so far.

How the numbers were worked out

  • Developed: the date the skill or agent file was first written, checked against Claude session logs.
  • Build time: an estimate of hands-on time. It counts active minutes in each session from your first request to the last change to the skill. Breaks longer than 5 minutes are capped at 5 minutes.
  • Not counted: time spent running a skill after it was built (for example, publishing reports or doing job scans), and supporting pieces built separately, such as the speed-test collector (about 45 min, 19 to 25 Aug).
  • Shared sittings: Company Briefs, Company Interview Brief and Interview Brief Web Report were built together on 28 and 29 Sep (about 1h 50m in total). New GitHub Site and Update Live Site were built together in about 20 min. Their time is split across the skills.
  • Portfolio website: time covers the personal brand sessions from 26 Jul to 10 Sep, which also included small related pieces (a role-themes diagram and a link from the Data Strategy & Evolution page). Treat it as within plus or minus 30%.
  • ACCA Seat Planner: time covers the Claude Code sessions from 12 to 16 Oct. Versions 1 to 17 were built earlier in a claude.ai chat, then handed over to Claude Code on 12 Oct; that chat time is not counted. Use is not tracked, because the app runs on each coach's phone with no analytics.
  • ChatGPT builds: dates, results and obstacles come from your own ChatGPT inventory (18 Oct). Build dates are when the related chat was created; build time was not recorded.
  • Results and obstacles: counts come from output folders, run logs, trackers and your GitHub repo list as at 18 Oct. Obstacles are the problems raised in build sessions and how each was handled.
  • Status: set by Adam, as at 18 Oct 2026.
  • Times used and run time: counted from Claude Code session logs, the scheduled task history and the cloud routine history, up to 18 Oct. A use is one slash command or scheduled run. Run time is the time Claude spent working on each run, leaving out time spent waiting on you. Portfolio views come from GoatCounter. ChatGPT counts assume one run a day and have not been checked.
  • Version updates: the number of times each build was changed after it was first built, counted as separate editing sittings in the session logs. The portfolio and seat planner use their published version history instead. ChatGPT figures come from your inventory.
  • Precision: figures are rounded to the nearest 5 minutes. Treat them as within plus or minus 25%.
